# Release notes - v0.3.0

Welcome to the first release notes of Katana. The project has supported my work in both a personal and professional capacity, and with its recent adoption by [Zierhut IT GmbH](https://zierhut-it.de/) in the [ZubZet](https://zubzet.com/) framework as the rendering engine. It provides me immense joy to know that the project may have potential for wider adoption.

## What's new

Katana v0.3 release ships with a minor bugfix, three new features and, some quality of life improvements.

### Inline @php directive support

`@php .... @endphp` directive has been supported by Katana for a long time. However, the engine lacked support for inline PHP directive when you needed to evaluate expressions.

```
@php($time = time())
```

### Use directive support

Introduction of the `@use` directive eliminates the need for yet another `@php` block in your template files when you needed to import a specific class. It is one of the most interesting updates in the lineup because of its backwards compatibility requirements.

[Video: How @use was implemented](https://youtu.be/4N-5L_VyUTI)

```
@use(Engine\Katana)

{{ Katana::VERSION }} -> 0.3.0
```

### Custom echo handlers

Katana can now render objects based on a concrete class directly using escaped output `{{ }}`  and unescaped output `{!! !!}` syntax via registered closures. Currently the engine only supports closure based syntax and just like Laravel blade intersection and union types are not supported.

```php
<?php
$blade->stringable(fn(DateTime $date) => $date->format("Y-F-d"));
```

```
{{ $date }} // Outputs using the registered closure
```

### Custom directives

The engine now supports registering custom directives, allowing you to create domain specific directives, for a richer and more productive development experience.

```php
<?php
$blade->directive('wphead', fn() => "<?php wp_head(); ?>");
```

```blade
<head>
    ....
    @wphead
</head>
```

### Bugfix: Default attribute merging

Update corrects the behaviour when components with `{{ $attributes->merge(['x-data' => 'hello']) }}` are called with an override attribute the default value would get concatenated to the override value. Now defaults values are replaced, class attributes continue to work as it.
